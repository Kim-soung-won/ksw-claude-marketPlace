# 도메인 테스트 존재와 명세 연결 검사

도메인 리뷰의 기본 검사다. 파일의 존재, 명세와의 연결, 실행 결과를 별도로 보고한다.
기본은 읽기 전용 정적 확인이며 테스트를 자동 생성·수정하거나 실행하지 않는다.
테스트 품질의 상세 감사와 실행은 별도 범위로 프론트엔드 절차에 연결한다.

## 1. 실제 테스트 위치 조사

프로젝트의 테스트 설정·패키지 스크립트·기존 작업 기록에서 테스트 루트와 수집/제외
패턴을 확인한다. `test/` 미러 경로 외에 `tests/`, 소스 옆 테스트, `__tests__`,
워크스페이스별 설정과 사용자 지정 경로도 확인한다. 설정에 없는 경로를 임의로 요구하지 않는다.

프로젝트 루트에서 후보를 찾는 예:

```bash
rg --files -g '*test*' -g '*spec*' -g '!node_modules' -g '!dist' -g '!coverage'
```

위 검색은 출발점이다. 실제 설정이 다른 파일명을 수집하면 그 패턴도 조사한다.
무시되거나 접근할 수 없는 경로·외부 저장소가 있으면 탐색 한계를 기록한다.
관련 범위를 충분히 탐색하지 못했을 때는 테스트 없음으로 단정하지 않는다.

## 2. 도메인과 테스트 연결

스킬의 API·도메인 불변식·시나리오에서 검토할 기능을 추출하고 테스트 본문을 읽는다.
요구사항 ID, 근거 주석, 대상 모듈의 직접/간접 import, API 경로, 사용자 행동과 단언으로
연결을 확인한다. 파일명에 도메인 이름이 없더라도 실제 흐름을 검증하면 관련 테스트다.
동일 이름만 있거나 fixture·MSW 핸들러·스냅샷 파일만 있는 것은 테스트 확보가 아니다.

| 명세 | 우선 찾을 검증 대상 |
|---|---|
| API 계약 | 요청 직렬화·응답 스키마·오류 계약을 검증하는 테스트 |
| 도메인 규칙 | Entity 변환·불변식·경계값을 검증하는 테스트 |
| UI 시나리오 | 사용자 행동과 화면 결과를 연결하는 통합 또는 E2E 테스트 |

단위/통합/E2E 수준을 기록하되 모든 기능에 모든 종류를 일률적으로 요구하지 않는다.
하나의 통합 테스트가 여러 계약을 검증할 수도 있다. 핵심 성공·실패 시나리오가 실제
단언에 연결되는지 확인하고, 누락은 해당 명세 항목을 근거로 지적한다.
코드에서만 관찰한 특성화 테스트는 존재하더라도 승인된 명세 테스트와 구분한다.

## 3. 판정

| 상태 | 기준 | 보고 |
|---|---|---|
| 있음 | 대상 행동에 연결된 테스트 본문과 단언을 확인 | 경로·케이스·명세 근거. 실행 통과를 뜻하지 않음 |
| 일부 있음 | 일부 명세만 연결되고 나머지 핵심 동작은 연결되지 않음 | 연결된 항목과 누락 항목을 각각 기록 |
| 없음 | 확인한 탐색 범위에서 관련 테스트를 찾지 못함 | 탐색한 경로·설정과 누락 기능 기록 |
| 골격/비활성만 있음 | 빈 본문, todo/skip, 비활성 suite, 검증 없는 골격만 존재 | 파일 존재와 유효한 검증 부재를 구분 |
| 확인 불가 | 접근·설정·간접 연결을 확인할 근거 부족 | 확인하지 못한 범위와 필요한 정보 기록 |
| 해당 없음 | 그 종류의 검증 대상이 없는 범위 | 이유 기록. UI가 없는 계약에 UI 테스트를 요구하지 않음 |

수집 설정에서 제외된 테스트는 파일 존재를 기록하되 기본 실행 대상 아님을 표시한다.
별도 실행 명령이 확인되면 함께 기록한다. 실행 여부는 `미실행` 또는 실제 증거가 있는
결과만 적는다. 과거 로그는 시점·대상 버전이 일치하는지 확인하고 현재 통과로 재사용하지 않는다.
파일 수나 연결 개수로 코드 커버리지 또는 명세 완전성을 추정하지 않는다.

## 4. 단계별 등급과 후속 작업

- 구현된 기능에서 핵심 명세의 테스트 없음·일부 누락·골격/비활성만 존재하면 WARNING.
- 계약 준비 등 테스트 작성 전 단계임이 확인되면 미작성 예정 INFO. 선작성이라는 이유로
  계속 면제하지 않는다. 명세 테스트 작성 완료·검토 준비를 주장한 범위에서 누락되면 WARNING.
- 테스트 존재만으로 기능 완료·승인을 판정하지 않는다. EXPECTED_RED는 누락이나 결함으로
  자동 분류하지 않으며, 단계·근거와 실행 증거를 함께 확인한다.
- 확인 불가는 검사 한계 INFO로 남기고, 핵심 범위가 미확인임을 요약에서 명시한다.
- 특성화 테스트는 미승인 현재 동작으로 보고하고 유지할 명세인지 검토 대상으로 남긴다.

테스트 작성·상세 감사가 필요하면 `frontend-support-plugin`의 실제 설치 위치에서
`frontend-workflows` 또는 `domain-ui-tdd`를 찾아 연결한다. 없으면 필요한 기능·명세 근거·
후보 경로를 반환한다. 없는 에이전트를 호출했다고 말하지 않는다. 도메인 지식 수정은
기존 관리자에게, 테스트 보강은 프론트엔드 절차에 전달하며 이 리뷰에서 자동 수정하지 않는다.
