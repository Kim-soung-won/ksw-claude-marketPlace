# domain-skill-reviewer — 결과 리포트 형식

> 이 파일은 `agents/domain-skill-reviewer.md`에서 분리된 정적 참고 자료다.
> 5단계(우선순위 분류 및 리포트 출력)에서 최종 결과를 출력하기 직전에 Read로
> 읽고 아래 형식 그대로 출력한다.

---

## 결과 리포트 형식

```
## Skill Review Report

📊 검토 범위: {Focused / Full Scan} — {n}개 스킬
📅 검토 기준: 코드 정합성 검사 {포함 / 미포함 (src/ 없음)}
비교 목적: {현재 계약 감사 / 선작성 계약 검토}
기능별 차이: {명세와 일치 / 미구현 예정 / 명세 충돌 / 미승인 현재 동작}
실행 계약 참조: {스키마 파일·export와 근거 문서}

---

### 🔴 CRITICAL ({n}건)

| 스킬 | 항목 | 내용 | 권장 조치 |
|------|------|------|----------|
| `{스킬명}` | 끊긴 링크 | `[[{링크명}]]` — 대상 스킬 없음 | domain-skill-manager로 링크 수정 |
| `{스킬명}` | 타입 충돌 | `{TypeName}` — `[[{스킬A}]]`와 구조 불일치 | 어느 쪽이 최신인지 확인 후 통일 |

---

### 🟡 WARNING ({n}건)

| 스킬 | 항목 | 내용 | 권장 조치 |
|------|------|------|----------|
| `{도메인}` | trio 미완성 | `_scenario` 없음 | domain-skill-manager로 생성 |
| `{스킬명}` | 고위험 미확인 | unconfirmed {n}개 | 협업자와 확인 후 domain-skill-manager로 업데이트 |

---

### 🟢 INFO ({n}건)

| 대상 | 항목 | 내용 |
|------|------|------|
| `{스킬명}` | collaborators 없음 | 출처 불명 — 작성자 추가 권장 |
| `{도메인}` | 스킬 없음 | `{도메인}.service.ts` 존재 — 스킬 생성 고려 |

---

### 📋 전체 trio 현황

| 도메인 | _api | _domain | _scenario | 상태 |
|--------|------|---------|-----------|------|
| `{도메인}` | ✅ | ✅ | ❌ | 미완성 |

---

### 🧪 도메인 테스트 현황

탐색 범위·수집 설정: {확인한 경로·설정, 제외·접근 불가 범위}
검사 방식: 정적 확인 / 실행 상태: {기본 미실행, 실제 실행 증거가 있으면 시점·버전·결과}

| 도메인·기능 | 명세 항목/요구사항 ID | 종류 | 존재 상태 | 테스트 경로·케이스와 연결 근거 | 누락·후속 |
|---|---|---|---|---|---|
| {대상} | {API/불변식/시나리오} | {단위/통합/E2E} | {있음/일부 있음/없음/골격·비활성만 있음/확인 불가/해당 없음} | {경로와 실제 단언, 특성화 여부} | {단계와 필요한 작업} |

---

### ✅ 이상 없는 스킬 ({n}개)

{스킬명 목록}

---

> CRITICAL {n}건 · WARNING {n}건 · INFO {n}건
> 지식 수정: domain-skill-manager / 테스트 보강·상세 감사: frontend-support-plugin의 절차.
```

테스트 표는 누락 없이 출력한다. 테스트가 없거나 확인 불가인 경우에도 범위와 이유를
남긴다. 파일 존재를 실행 PASS나 코드 커버리지로 표현하지 않는다. 테스트 검사가 미확인인
스킬은 전체 이상 없음으로 묶지 않고 지식 검사 결과와 검사 한계를 구분한다.
