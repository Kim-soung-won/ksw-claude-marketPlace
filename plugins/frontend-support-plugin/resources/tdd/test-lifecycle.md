# 테스트 생명주기와 완료 판정

단위·통합 테스트 작성자와 감사자가 공유하는 원본이다. 기존 작성 규약의
통과 요구는 `verify` 모드에 적용하며, `spec-first`는 아래 완료 기준을 적용한다.

## 모드와 근거

- `verify`(기본): 구현된 기능을 검증한다. 실행·통과를 확인해야 완료다.
  구현 결함으로 실패하면 실패를 보고하고 반환한다. 작성자의 범위를 넘어 구현을
  수정하거나 끝없이 재시도하지 않는다.
- `spec-first`: 신규·변경 기능의 명세 테스트 또는 기존 기능의 명세 확보다.
  실제 실행, 단언 근거, 케이스별 결과 분류까지가 작성 완료 조건이다.
  작성 완료는 기능 구현 완료·개발자 승인과 다르다.
- `characterization`은 모드가 아니라 **근거 구분**이다. 문서·업무 규칙이 없는
  기존 동작을 관찰해 외부 입출력·사용자 행동으로 기록한다. 승인 전에는 요구사항의
  정답이 아니다. 내부 필드·호출 순서·구현 계산을 복사한 테스트는 여전히 부적합하다.

각 케이스에는 안정적인 요구사항 ID와 근거(문서 위치·API operation·도메인 규칙 또는
현재 동작 관찰)를 주석으로 남긴다. 이름과 본문은 전제→행동→기대 결과를 읽을 수
있어야 한다. 업무 정책이 충돌하면 최신 코드나 Swagger를 임의로 우선하지 않는다.
Swagger는 전송 계약의 근거이며 화면 노출·권한·업무 상태 전이를 자동 결정하지 않는다.

## 실제 실행 결과

| 분류 | 판정 | 다음 행동 |
|---|---|---|
| PASS | 근거 있는 동작을 실제로 단언하고 통과 | 기존 기능이면 첫 실행 GREEN도 정상. 인위적으로 코드를 깨지 않는다 |
| EXPECTED_RED | 실행 환경과 진입점은 정상이며 목표 행동 부재 때문에 단언 실패 | 실패 단언·기대값·관찰값을 기록하고 검토 대상으로 제출 |
| SPEC_CONFLICT | 문서·요구·기존 동작 중 무엇이 맞는지 미확정 | 양쪽 근거를 제시하고 해당 기대 동작의 확정을 기다림 |
| CHARACTERIZATION | 현재 동작을 기록했으나 요구사항으로 미승인 | 실행 PASS/FAIL을 별도 기록하고 개발자에게 유지 여부 검토 요청 |
| BLOCKED | 의존성·import·타입·설정·환경 오류 또는 실행 권한 없음 | RED로 계산하지 않고 해결 방법과 미검증 범위를 보고 |
| REGRESSION | 기준선에서 통과하던 관련 테스트가 새로 실패 | 새 RED와 분리하고 원인을 해결해야 최종 완료 |

`skip`, `todo`, 빈 테스트, 무조건 실패, 무조건 통과는 명세 완료로 세지 않는다.
일부 케이스가 앞선 실패 때문에 실행되지 않았다면 미실행으로 기록한다. 한 개의
버튼 누락 때문에 뒤의 모든 요구가 검증됐다고 주장하지 않는다. 최종 GREEN에서는
실제 내부 모듈과 HTTP 경계까지 연결된 통합 테스트 실행 증거가 필요하다.

## 최소 골격과 쓰기 범위

테스트 작성자는 테스트·fixture·MSW 핸들러를 수정한다. 소스의 최소 export·함수
시그니처·렌더 가능한 빈 컴포넌트가 필요하면 하네스에 경로와 이유를 반환한다.
하네스만 요청 범위 내에서 골격을 준비한다. 골격에는 업무 분기·정답 데이터·
실제 사용자 동작을 넣지 않고, 기존 구현을 빈 골격으로 대체하지 않는다.
골격이 허용되지 않으면 해당 케이스는 BLOCKED이며 유효 RED라고 보고하지 않는다.
의존성과 공용 렌더 환경도 하네스가 기존 권한 안에서 준비하며 작성자는 부족분을 보고한다.

검토 전 UI 동작을 구현해서 테스트를 통과시키지 않는다. 승인 후에도 테스트 작성자의
권한이 자동으로 구현 권한으로 바뀌지는 않는다. 구현은 하네스의 구현 단계가 맡는다.

## 승인된 테스트 유지

GREEN에서는 기대 동작·단언·fixture 계약·MSW 경계를 약화하거나 테스트를 제외해서
통과시키지 않는다. 명세 오류를 발견하면 근거와 변경 diff를 제시하고 영향받는
요구사항의 승인을 갱신한다. import·하니스 오류 등 기대 동작이 그대로인 수정은
이유와 diff를 기록하고 재실행한다. 동작 변경 여부가 불분명하면 명세 변경으로 다룬다.
범위 밖 실패는 기준선과 비교해 보고하고 전체 통과라고 표현하지 않는다.
