# 셸 관용구 (bash·sh)

적용 대상: `.sh`·`.bash` 파일, `#!/bin/bash`·`#!/usr/bin/env bash`·`#!/bin/sh` shebang,
확장자 없이 `bash x`/`sh x`로 실행하는 파일.

## 목차

1. 종료·오류 처리
2. 파라미터 확장
3. 반복과 glob
4. 외부 명령 차이
5. 실행 방식과 상태 공유
6. 위험 패턴
7. 순서도 반영 요약
8. 정적 점검

## 1. 종료·오류 처리

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| `set -e` | 처리되지 않은 명령 실패에서 즉시 종료. 단 `if`·`while` 조건, `!` 부정, `&&`·`\|\|` 목록의 마지막이 아닌 명령에서는 종료하지 않는다. 그런 문맥에서 호출된 **함수 본문 전체**에서도 꺼진다 | 실패할 수 있는 단계마다 "실패 → exit(set -e)" 간선. 여러 단계가 같으면 오류 종료 노드 하나로 합친다 |
| `X=$(cmd)` + `set -e` | 대입문의 상태는 `cmd`의 상태라 실패 시 **메시지 없이** 종료. `grep`이 일치하지 않아도(상태 1) 종료한다 | 숨은 종료로 그리고 '주의할 점'에 적는다. 예: `OLD_TAG_LINE=$(grep -m1 '^ *tag:' ...)` |
| `local X=$(cmd)`·`export X=$(cmd)` | `local`·`export`의 상태(0)가 실패를 가린다 | 실패 간선을 그리지 않고 "실패 무시"로 해설 |
| `echo "... $(cmd)"` | 치환 안 실패는 감지되지 않는다 | 그리지 않음 |
| `set -u` | 정의되지 않은 변수 참조 시 종료. `${VAR:-기본값}`은 예외 | 필수 환경 변수가 있으면 시작 직후 오류 종료 간선 |
| `set -o pipefail` | 파이프라인 중 하나라도 실패하면 실패. 없으면 **마지막 명령의 상태만** 본다 | 없으면 `a \| head -1` 같은 파이프의 앞 단계 실패는 그리지 않는다 |
| `cmd \|\| true`, `cmd \|\| echo ...` | 실패를 무시하고 진행 | 분기 없이 노드 라벨에 "(실패 무시)" |
| `cmd \|\| { ...; continue; }` | 실패 시 블록 실행 후 다음 반복 | 반복 subgraph 안에 "다음 반복" 간선 |
| `cmd \|\| { ...; exit 1; }` | 실패 시 메시지 후 종료 | 오류 종료 간선 |
| `[ cond ] && X=...` | 조건이 거짓이면 이 줄의 상태가 1. `set -e`로 종료하지는 않지만 함수·스크립트의 **마지막 줄**이면 반환 코드가 1이 된다 | 마지막 줄이면 '주의할 점'에 적는다 |
| `((i++))` (`i`가 0) | 결과 0은 상태 1이라 `set -e`에서 종료 | 숨은 종료로 그린다 |
| `trap '...' EXIT`/`ERR` | 종료 시 정리 코드 실행 | `restore` 노드로 모든 종료 노드 앞에 연결하거나, 다이어그램 아래에 한 줄 설명 |

## 2. 파라미터 확장

해설 표에는 실제 값으로 결과를 보여 준다.

| 표현 | 의미 | 예 (`V="auth:ai_central_auth"`, `T="1.9.7-ssis-prod"`) |
|---|---|---|
| `${V%%:*}` | 뒤에서 가장 긴 `:*` 제거 → 첫 `:` 앞 | `auth` |
| `${V%:*}` | 뒤에서 가장 짧은 `:*` 제거 → 마지막 `:` 앞 | `auth` |
| `${V##*:}` | 앞에서 가장 긴 `*:` 제거 → 마지막 `:` 뒤 | `ai_central_auth` |
| `${V#*:}` | 앞에서 가장 짧은 `*:` 제거 → 첫 `:` 뒤 | `ai_central_auth` |
| `${T%%-*}` | 첫 `-` 앞 | `1.9.7` |
| `${V:-d}` / `${V:=d}` | 비었으면 `d` 사용 / 사용하면서 대입 | — |

구분자가 없으면 원문이 그대로 남는다. 이를 이용한 `[ "$PREFIX" = "$ENTRY" ] && PREFIX="$MODULE"` 같은
기본값 처리도 함께 해설한다.

## 3. 반복과 glob

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| `for f in dir/*.tar; do [ -e "$f" ] \|\| continue` | 일치 파일이 없으면 패턴 문자열 자체가 한 번 들어오므로 건너뛴다(`shopt -s nullglob`이면 반복 0회) | 그리지 않고 해설 표에만 |
| `ls dir/*.tar \| head -1` | 여러 개면 정렬상 첫 번째만 사용. 없으면 빈 값(`2>/dev/null`) | 뒤따르는 `[ -z ]` 검사를 분기로 그린다 |
| `cmd \| while read ...; do ... exit 1; done` | 파이프 오른쪽은 서브셸이라 `exit`가 **반복만** 끝내고 스크립트는 계속된다. 반복 안에서 바꾼 변수도 사라진다 | 종료 노드가 아니라 "반복 중단"으로 그리고 '주의할 점'에 적는다 |
| `( cd x && ... )` | 서브셸 안 `cd`·변수·`exit`는 밖에 영향 없음 | 한 노드로 요약 |

## 4. 외부 명령 차이

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| `sed -i 's/a/b/' f` | GNU 형태. BSD·macOS sed는 `-i ''`처럼 백업 접미사 인자가 필요해 같은 줄이 실패하거나 엉뚱한 파일을 만든다 | '주의할 점'에 실행 환경 전제(GNU/Linux) 기록 |
| `sed -i "${N}a\\` + 개행 + `${LINE}"` | 큰따옴표 안 `\\`가 `\`가 되어 `Na\` + 개행 + 텍스트, 즉 N번째 줄 **뒤에** 한 줄 삽입. `i\`는 앞, `c\`는 교체. 텍스트 앞 공백 처리는 구현마다 달라 YAML 들여쓰기에 영향을 줄 수 있다 | "앵커 뒤 삽입" 한 노드. 삽입 후 검증이 있으면 분기로 그린다 |
| `grep -q` | 출력 없이 일치 여부만 상태로 반환 | 분기 조건 라벨로 쓴다 |
| `grep -m1` | 첫 일치만 | 해설 표 |
| `curl -sS` | 진행 표시는 끄되 오류는 출력. HTTP 4xx·5xx는 실패로 보지 않는다(`-f`가 있어야 실패) | 상태 코드 검사 분기가 따로 있는지 확인해 그린다 |
| `helm uninstall` → `helm install` | 두 명령 사이 서비스가 내려간다. `upgrade --install`과 다르다 | 부수효과 표에 중단 기록 |

## 5. 실행 방식과 상태 공유

| 호출 | 프로세스 | 변수·`cd`·`set` 옵션 | 하위의 `exit` | 순서도 |
|---|---|---|---|---|
| `bash x.sh` | 새 프로세스. shebang 무시, 실행 권한 불필요 | 공유 안 함 | 하위만 종료, 상위는 종료 코드를 받음 | 서브루틴 노드 `[[x.sh]]` + 종료 코드 간선 |
| `./x.sh` | 새 프로세스. 실행 권한과 shebang 필요. shebang이 없으면 **호출한 셸**이 해석기를 정한다 | 공유 안 함 | 위와 같음 | 위와 같음. shebang 누락은 '주의할 점' |
| `source x.sh`, `. x.sh` | 같은 프로세스 | 모두 공유 | **상위까지** 종료 | 하위 단계를 상위 순서도에 펼치거나, 노드에 "(source — exit 시 상위도 종료)" 표기 |

- `exit`는 스크립트 전체를, `return`은 함수(또는 source된 파일)만 끝낸다. 함수 안 `exit 0`은
  "함수 정상 반환"이 아니라 **스크립트 종료**다 — 숨은 조기 종료의 대표 사례로 `skip` 노드로 그린다.
- `cd`는 이후 모든 상대 경로(`./Chart`, `./image_push.sh`)의 기준을 바꾼다. 반복 안 `cd`는
  다음 반복과 반복 뒤 코드에도 남는다. `set -e` 없이 `cd`가 실패하면 엉뚱한 위치에서 계속된다.
- `if ! bash x.sh`처럼 하위 프로세스를 조건에 두어도 하위 스크립트 안의 `set -e`는 그대로 작동한다.
  꺼지는 것은 같은 프로세스 안 함수 호출의 경우다.

## 6. 위험 패턴

분류·등급·완화 장치 판정은 `../risky-commands.md`를 따른다. 셸에서 특히 놓치기 쉬운 형태만 적는다.

- `rm -rf "$DIR/"*`·`rm -rf "$DIR"` — `DIR`이 비면 루트나 현재 위치를 지운다. `${DIR:?}` 유무를 본다.
- `> "$FILE"` 리다이렉트 — 명령이 실패해도 파일은 이미 비워져 있다.
- `sed -i` — 백업 접미사(`-i.bak`)나 직전 `cp`가 없으면 백업 없음.
- `cp`·`mv` — `-n`·`-i` 없이 기존 파일을 조용히 덮어쓴다.
- `curl ... | sh`·`bash <(curl ...)` — 내려받은 코드를 검증 없이 실행.
- `/tmp/고정이름` — 동시 실행·다른 사용자와 충돌. `mktemp` 사용 여부를 본다.
- `echo "$TOKEN"`·`set -x` — 비밀값이 로그에 남는다.

## 7. 순서도 반영 요약

- 모든 `exit` 지점, `set -e`로 생기는 숨은 종료(`$(grep ...)` 대입 등)를 종료 노드로 그린다.
- `|| true`·`|| echo`는 분기 없이 "(실패 무시)" 라벨.
- `exit 0`이 이후 단계를 건너뛰면 `skip` 클래스와 점선 간선.
- 백업 → 실패 시 `cp "$BACKUP" ...` 복원은 `restore` 노드.
- 하위 스크립트 호출은 호출 방식(`bash`/`./`/`source`)을 노드 라벨이나 해설 표에 적는다.
- 위험 패턴 노드는 `⚠️` 라벨과 `danger`/`guarded` 클래스.

## 8. 정적 점검

1. 문법: `bash -n <파일>` (sh 대상이면 `sh -n`). 항상 실행한다.
2. ShellCheck가 설치되어 있으면 `shellcheck -x <파일>`을 실행한다. shebang이 없으면 `-s bash`를 붙인다.
   경고는 '주의할 점'에 규칙 번호(예: SC2155 — `local`이 치환 실패를 가림)와 영향만 요약한다.
   설치되어 있지 않으면 설치하지 않고 "ShellCheck 미실행"을 적는다.
