# Node 관용구

적용 대상: `.js`·`.mjs`·`.cjs` 파일, `#!/usr/bin/env node` shebang, `package.json`의 `scripts`가 `node <파일>`로 호출하는 진입점.

## 1. 종료

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| `process.exit(n)` | 즉시 종료. 대기 중인 Promise·타이머, 파이프로 보내는 중인 stdout 출력, `await` 뒤의 `finally`가 실행되지 않을 수 있다 | 종료 노드. 그 뒤에 남은 비동기 작업이 있으면 '주의할 점' |
| `process.exitCode = n` | 종료 코드만 정하고 이벤트 루프가 비면 종료 | 종료 노드는 "작업 완료 후 exit n" |
| 처리되지 않은 예외(동기) | 스택 출력, 종료 코드 1 | 오류 종료 노드로 모은다 |
| 처리되지 않은 Promise 거부 | Node 15 이상 기본값에서 프로세스가 종료(코드 1). `await`하지 않은 Promise는 **뒤 코드가 먼저 진행된 뒤** 나중에 종료된다 | 거부 지점에서 오류 종료로 가는 점선 간선과 "(나중에 종료)" 라벨 |
| `catch(() => {})`, `.catch(console.error)` | 실패를 삼키고 진행 | "(실패 무시)" 라벨 |

## 2. 자식 프로세스

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| `execSync(cmd)` | 셸로 실행, 0이 아니면 **예외**. 잡지 않으면 스크립트 종료 | 오류 종료 간선 |
| `spawnSync(cmd, args)` | 예외 없이 `{ status, error }` 반환. 검사하지 않으면 실패를 모름 | 검사가 없으면 "(실패 무시)" |
| `exec(cmd, cb)`·`spawn(...)` | 비동기. 호출 다음 줄이 자식 종료를 기다리지 않고 바로 실행 | 병렬 진행으로 그리거나, 완료 콜백·`await` 지점에서 합류 |
| `util.promisify(exec)` + `await` | 0이 아니면 거부. `exec`는 출력 버퍼 한도(`maxBuffer`)를 넘으면 실패 | 오류 종료 간선 |
| `stdio: "inherit"` | 자식 출력이 그대로 터미널에 나온다 | 그리지 않음 |

## 3. 비동기 실행 순서

| 관용구 | 실제 동작 | 순서도 반영 |
|---|---|---|
| 최상위 `await` | ESM(`.mjs` 또는 `"type": "module"`)에서만 가능. CommonJS에서는 문법 오류라 `(async () => { ... })()` 래퍼를 쓴다 | 래퍼 함수 본문을 순서도의 시작으로 본다 |
| `arr.forEach(async x => { await ... })` | `forEach`는 기다리지 않는다. 반복이 즉시 끝나고 다음 코드가 실행된 뒤 본문들이 **동시에** 진행된다 | subgraph 제목에 "병렬·기다리지 않음". 뒤 단계가 결과에 의존하면 '주의할 점' |
| `for (const x of arr) { await ... }` | 하나씩 순서대로 | 일반 반복 subgraph |
| `await Promise.all([...])` | 동시에 시작, 하나라도 거부되면 즉시 거부. 나머지 작업은 멈추지 않고 계속 실행된다 | 병렬 subgraph + 오류 간선 |
| `Promise.allSettled` | 전부 끝날 때까지 기다리고 결과를 모은다 | 루프 뒤 일괄 판정 분기 |
| 동기 코드 → Promise 콜백 → 타이머 | 같은 틱의 동기 코드가 먼저 끝까지 실행된다 | 순서가 소스 순서와 다르면 실제 순서로 그린다 |

## 4. 위험 패턴

분류·등급·완화 장치 판정은 `../risky-commands.md`를 따른다. Node에서 특히 놓치기 쉬운 형태만 적는다.

- `fs.rmSync(p, { recursive: true, force: true })` — `force`가 존재하지 않는 경로 오류도 숨긴다. `p` 계산 결과를 본다.
- `fs.writeFileSync` — 대상을 바로 덮어쓴다. 임시 파일 후 `fs.renameSync` 여부를 본다.
- `execSync`에 템플릿 문자열로 경로·입력을 끼워 넣는 형태 — 셸 위험 패턴이 그대로 적용된다.
- `forEach(async ...)` 안의 삭제·배포 — 여러 대상이 동시에 바뀌어 중간 실패 시 상태가 섞인다.
- `os.tmpdir()` 아래 고정 이름, 비밀값 `console.log`·하드코딩.

## 5. 순서도 반영 요약

- 시작점은 최상위 실행부(또는 async 래퍼). 함수 정의는 호출 지점에서 한 노드로 요약한다.
- `await` 없는 비동기 호출은 병렬로, `forEach(async ...)`는 "기다리지 않음"으로 표시한다.
- `process.exit`는 종료 노드, 그 뒤 비동기 작업 손실 가능성은 '주의할 점'.
- `execSync`·`await`된 거부는 오류 간선, `spawnSync`·삼킨 `catch`는 "(실패 무시)".
- 위험 패턴 노드는 `⚠️` 라벨과 `danger`/`guarded` 클래스.

## 6. 정적 점검

1. 문법: `node --check <파일>`. 항상 실행한다.
2. 프로젝트에 이미 설정된 린터(eslint 등)가 있으면 그 설정으로 실행해 경고를 '주의할 점'에 요약한다.
   새로 설치하지 않는다.
