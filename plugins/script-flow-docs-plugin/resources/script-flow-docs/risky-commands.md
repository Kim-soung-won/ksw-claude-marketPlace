# 주의할 명령 판정 기준

FLOW.md를 작성·갱신할 때마다 폴더의 모든 스크립트에서 아래 명령을 찾아 등급과 완화 장치를 판정하고,
FLOW.md의 "⚠️ 주의할 명령" 표(형식 문서 2절)와 순서도의 위험 노드 표기(Mermaid 규칙 3절)에 반영한다.
언어별 특유 패턴은 `idioms/<언어>.md`의 "위험 패턴" 절에 있고, 판정은 이 문서 기준을 따른다.

## 목차

1. 판정 절차
2. 위험 명령 분류
3. 위험을 키우는 조건
4. 완화 장치 판정
5. 권장 수정안 작성법

## 1. 판정 절차

1. 아래 2절 분류에 해당하는 명령을 모두 찾는다. 같은 명령이 루프 안에 있으면 한 행으로 쓰고 "루프 안"을 영향에 적는다.
2. 기본 등급을 정한다(2절 표).
3. 3절 조건이 하나라도 있으면 **중간 → 높음**으로 올린다(높음은 그대로).
4. 4절 기준으로 완화 장치를 판정한다. 완화 장치가 있어도 등급은 낮추지 않고, 표의 "완화 장치" 칸과
   순서도 클래스(`guarded`/`danger`)로 구분한다.
5. 완화 장치가 없으면 "권장" 칸에 5절 형식의 구체적 수정안을 쓴다.
6. **완화 장치 없는 높음 등급**은 작업 응답에도 목록으로 요약해 사용자에게 알린다.

## 2. 위험 명령 분류

| 분류 | 명령 예 | 기본 등급 |
|---|---|---|
| 삭제·되돌릴 수 없음 | `rm -rf`, glob을 쓰는 `rm -f`, `find ... -delete`, `kubectl delete`, `helm uninstall`, `docker rmi`·`docker system prune`, 조건 없는 SQL `DROP`·`TRUNCATE`·`DELETE`, Python `shutil.rmtree`·`os.remove`, Node `fs.rmSync`·`fs.unlinkSync` | 높음 |
| 덮어쓰기·제자리 수정 | 대상이 이미 있는 `cp`·`mv`, `>` 리다이렉트, `sed -i`, `truncate`, Python `open(p, "w")`, Node `fs.writeFileSync` | 중간 |
| 서비스 중단·운영 영향 | `helm uninstall` → `helm install` 재배포(다운타임), `kubectl rollout restart`, `kubectl scale --replicas=0`, `systemctl stop`·`restart`, `reboot` | 높음 |
| 권한·보안 | `chmod 777`, 내려받거나 외부에서 온 파일에 `chmod +x` 후 실행, `sudo`, `curl ... \| sh`, 비밀값 출력·하드코딩, `/tmp` 고정 경로 파일 | 중간 (`curl \| sh`·비밀값 하드코딩은 높음) |

`helm uninstall`처럼 두 분류에 걸치면 높은 쪽 등급을 쓰고 영향 칸에 둘 다 적는다.

## 3. 위험을 키우는 조건

| 조건 | 예 | 확인 방법 |
|---|---|---|
| 변수가 비면 경로가 바뀜 | `rm -rf "$DIR/"*` — `DIR`이 비면 `/*` | `${DIR:?}` 또는 사전 `[ -n "$DIR" ]` 검사 유무 |
| 백업 없음 | `sed -i`로 원본만 수정 | 직전 `cp ... .bak` 또는 `.bak` 접미사 유무 |
| 멱등 아님 | 재실행하면 줄이 중복 삽입되거나 백업이 덮어써짐 | "이미 적용됨" 검사 분기 유무 |
| 루프 안 반복 실행 | 모듈마다 `helm uninstall` | 루프 subgraph 안에 있는지 |
| 실패 후 계속 진행 | `set -e`(또는 예외 전파·`check=True`) 없이 다음 명령이 앞 결과에 의존 | 오류 처리 관용구 확인(`idioms/<언어>.md`) |

## 4. 완화 장치 판정

다음 중 하나 이상이 **같은 실행 경로에서 위험 명령보다 먼저 또는 실패 시** 동작하면 "있음"이다.
이름만 있고 실제 경로에서 건너뛸 수 있으면 "부분"으로 적고 이유를 쓴다.

| 완화 장치 | 인정 조건 |
|---|---|
| 백업 | 위험 명령 직전 같은 대상을 복사하고, 복사 실패 시 진행하지 않음 |
| 검증 후 복원 | 실행 후 결과를 검사해 실패 시 백업으로 되돌림 |
| 확인 프롬프트 | 사용자 입력(`read -p`, `input()`)으로 진행 여부를 묻고 기본값이 "중단" |
| dry-run | 플래그로 실제 변경 없이 미리보기 가능 |
| 사전 검사 | 대상 존재·변수 비어 있지 않음·멱등 검사로 위험 조건을 막음 |

판정 예(`web-patch0911`):

| 명령 | 완화 장치 판정 |
|---|---|
| `updataLayoutChart.sh`의 `sed -i` 키 삽입 | 있음 — 백업 + 삽입 검증 실패 시 복원 |
| `updataLayoutChart.sh`의 configmap `cp` 덮어쓰기 | 있음 — 백업(기존 백업은 유지). 단 검증·자동 복원은 없음 |
| `changeImage.sh`의 기존 tar `rm -f` (glob, 루프 안) | 부분 — `[ -e ]` 검사는 있으나 백업 없음 |
| `changeImage.sh`의 `sed -i` image.tag | 없음 — 백업 없음(교체 확인만 있음) |
| `changeImage.sh`의 `helm uninstall` → `install` | 없음 — 루프 안 다운타임, 실패 시 복원 없음 |

## 5. 권장 수정안 작성법

"주의하세요" 같은 일반론 대신 바로 적용할 수 있는 변경을 쓴다.

- 백업 없음 → `cp "$VALUES" "$VALUES.bak.$(date +%Y%m%d%H%M%S)"`를 수정 직전에 추가
- 변수 빈값 → `rm -rf "${DIR:?}/"*`
- 재배포 다운타임 → `helm upgrade --install "$RELEASE" ./Chart -n "$NS"`로 교체 검토
- `/tmp` 고정 경로 → `TMP=$(mktemp)` + `trap 'rm -f "$TMP"' EXIT`
- 확인 없는 운영 영향 → 시작 시 대상·네임스페이스를 출력하고 확인 프롬프트 또는 `--yes` 플래그 요구

스크립트를 실제로 고칠지는 사용자 요청 범위에 따른다. 문서화만 요청받았으면 권장 칸에만 쓰고 고치지 않는다.
