# 스크립트 흐름 문서화 (FLOW.md)

스크립트 문법만 보고는 실행 순서·조기 종료·실패 복원을 파악하기 어렵다. 스크립트가 있는 폴더마다
`FLOW.md` 하나를 두고, 코드가 **실제로** 하는 일을 다이어그램 중심으로 설명한다.

- 형식 원본: [FLOW.md 섹션 형식](../../resources/script-flow-docs/flow-doc-format.md)
- 다이어그램 규칙: [Mermaid 작성 규칙](../../resources/script-flow-docs/mermaid-rules.md)
- 위험 명령 판정: [주의할 명령 판정 기준](../../resources/script-flow-docs/risky-commands.md)
- 언어별 관용구: [셸](../../resources/script-flow-docs/idioms/shell.md),
  [Python](../../resources/script-flow-docs/idioms/python.md),
  [Node](../../resources/script-flow-docs/idioms/node.md)

## 대상 판정

다음 중 하나에 해당하는 파일이 대상이다.

- shebang(`#!`)이 있는 파일
- `scripts/`·`bin/`·배포·패치·마이그레이션 폴더의 실행 파일
- `bash x.sh`·`python x.py`·`node x.js`처럼 인터프리터로 직접 실행하는 진입점
  (`package.json`의 `scripts`가 호출하는 파일 포함)
- 사용자가 '스크립트'라고 부르는 파일

애플리케이션 소스(다른 모듈이 import하는 라이브러리, 컴포넌트, 서버 핸들러), 테스트 파일,
빌드 설정 파일은 대상이 아니다. 진입점 스크립트가 import하는 헬퍼 모듈은 별도 FLOW.md를 만들지 않고
진입점 순서도의 한 노드로 요약한다. 판정이 애매하면 사용자에게 확인한다.

## 작업 순서

다음 체크리스트를 응답에 복사해 진행한다.

```text
- [ ] 1. 대상 판정과 폴더 범위 확정
- [ ] 2. 폴더의 스크립트 전부 읽기
- [ ] 3. 해당 언어 관용구 파일만 읽기, 정적 점검 실행
- [ ] 4. 위험 명령 검사
- [ ] 5. FLOW.md 작성 또는 갱신
- [ ] 6. 렌더링 확인 (실패하면 고치고 다시 확인)
- [ ] 7. 응답에 완화 장치 없는 높음 등급 요약
```

1. **범위 확정** — 작성·수정하는 스크립트가 있는 폴더가 단위다. 하위 폴더에 스크립트가 있으면
   그 폴더에 별도 FLOW.md를 두고, 상위 FLOW.md는 링크만 건다.
2. **전부 읽기** — 수정 대상 하나가 아니라 폴더의 스크립트를 모두 읽는다. 오케스트레이터가 무엇을
   어떤 순서로 호출하는지, 하위 스크립트의 종료 코드가 상위에서 어떻게 해석되는지 확인해야 하기 때문이다.
   폴더 밖에서 호출하는 스크립트(대상 서버의 `image_push.sh` 등)는 읽을 수 있으면 읽고,
   없으면 "폴더 밖 — 동작 미확인" 외부 노드로 둔다.
3. **관용구** — 폴더에 쓰인 언어의 관용구 파일만 읽는다. `resources/script-flow-docs/idioms/`의
   파일 목록에서 각 파일 첫머리의 "적용 대상"(확장자·shebang)으로 고른다(위 링크에 없는 언어 파일도 포함).
   해당 언어 파일이 없으면 형식 문서만 적용하고 관용구는 직접 판단한다. 관용구 파일에 적힌 정적 점검 도구가 있으면 실행하고 결과를 반영한다.
4. **위험 명령 검사** — FLOW.md를 작성·갱신할 때마다 **항상** 수행한다. 판정 기준 문서에 따라
   폴더의 모든 스크립트에서 삭제·덮어쓰기·서비스 중단·권한/보안 명령을 찾아 등급과 완화 장치를 정한다.
   결과는 FLOW.md "⚠️ 주의할 명령" 표와 순서도의 `danger`/`guarded` 노드에 반영한다.
5. **작성** — 형식 문서의 섹션 순서를 따른다. 이미 FLOW.md가 있으면 바뀐 스크립트와 관련된
   섹션만 고친다. 문서화 중 버그·주석 불일치를 발견하면 스크립트를 임의로 고치지 않고
   '주의할 점'에 적은 뒤 사용자에게 보고한다(스크립트 수정 요청이면 수정과 문서를 함께 갱신).
6. **렌더링 확인** — Mermaid 규칙 문서의 검증 절차를 따른다. 오류가 나면 고치고 다시 확인하며,
   통과한 뒤에 완료로 보고한다.
7. **보고** — 완화 장치가 없거나 부분인 **높음** 등급 명령을 응답에 "위치 | 명령 | 영향 | 권장" 목록으로
   요약해 사용자에게 알린다. 해당 명령이 없으면 "완화 장치 없는 높음 등급 없음"이라고 쓴다.

## 동기화 규칙

- 스크립트를 바꾸는 **같은 변경**에서 FLOW.md도 갱신한다. 나중으로 미루지 않는다.
- 갱신이 필요한 변경: 단계 추가·삭제·순서 변경, 종료 지점(`exit`, 예외, 조기 반환), 분기 조건,
  백업·복원 경로, 외부 시스템 호출, 변경 대상 파일·리소스, 위험 명령 추가·삭제·완화 장치 변경.
- 출력 문구·주석·변수명만 바뀌면 FLOW.md에서 그 표현을 인용한 곳만 맞춘다.
- 관용구 해설은 줄 번호가 아니라 코드 표현으로 인용한다. 줄 번호는 수정마다 어긋난다.
- "⚠️ 주의할 명령" 표의 `파일:줄`은 스크립트를 바꿀 때마다 다시 확인한다.
- 스크립트를 삭제·이름 변경하면 폴더 실행 흐름과 해당 순서도 섹션도 함께 정리한다.

## README와 FLOW.md의 역할

| 문서 | 담는 내용 |
|---|---|
| `README.md` | 목적, 실행 환경, 실행 방법, 필요한 도구, 결과 해석, 롤백 명령 |
| `FLOW.md` | 실행 순서, 분기·종료 지점, 부수효과, 관용구 의미, 숨은 동작 |

FLOW.md는 실행 방법을 반복하지 않고, README는 단계별 동작을 다이어그램으로 다시 그리지 않는다.
README가 있으면 FLOW.md로 가는 링크 한 줄(`동작 흐름은 FLOW.md 참고`)을 추가한다.
README의 동작 설명이 코드와 다르면 코드를 기준으로 FLOW.md를 쓰고 불일치를 '주의할 점'에 적는다.

## 새 언어 추가

`resources/script-flow-docs/idioms/`에 `<언어>.md` 파일 하나만 추가하면 된다. 기존 파일과 같은 구성
(적용 대상 → 관용구 표 → 위험 패턴 → 순서도 반영 → 정적 점검)을 따르면 이 스킬 본문은 고치지 않아도 된다.
