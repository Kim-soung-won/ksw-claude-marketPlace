# 측정 방법 모음

지금까지 써 본 측정의 목록이다. 완전한 목록이 아니며, 필요한 측정이 없으면 만든다.
어떤 것을 쓸지는 이번 변경의 위험 가설에 따라 고른다([judgment.md](judgment.md)). `lib.cjs` 에 있는 함수는 이름을 적었다.

## 넓게 잡는 측정

특정 가설 없이도 문제를 드러내는 측정이다. 재려던 항목 밖의 문제를 잡는 데 쓴다.
값이 싸므로 레이아웃·로딩에 닿는 변경이면 대개 돌릴 가치가 있다. 돌리지 않았으면 보고서에 "측정하지 않음"으로 적는다.

| 대상 | 방법 |
|------|------|
| 폭별 넘침 | 창 폭 1440·1024·768·480 에서 `overflowReport` — 가로 스크롤 영역, 부모 밖으로 나간 요소, 말줄임 없이 잘린 글자 |
| layout shift | 이동 전에 `startLayoutShiftWatch`, 로딩 뒤 `collectLayoutShifts` — 누적 값과 밀린 요소 |
| 콘솔 오류 | `console` 의 error 와 `pageerror` 수집 |
| 서버 데이터 변경 여부 | `watchRequests(...).mutations()` — 조회용 POST 를 뺀 뒤 조작으로 새로 생긴 요청이 없는지 |

한 폭에서 정상이어도 다른 폭에서 깨질 수 있다. 다이얼로그는 창 폭에 따라 너비가 달라지므로 열린 상태에서 폭을 바꿔 잰다.

## 키보드와 포커스

| 대상 | 방법 |
|------|------|
| 열릴 때 포커스 진입 | 여는 버튼에 포커스를 두고 Enter 로 연 뒤 `focusInside` |
| Tab 가두기 | `tabTrap(selector, 30)` — 한 번이라도 밖으로 나가면 실패 |
| 닫은 뒤 포커스 복귀 | Escape 후 `active` 가 여는 버튼인지 |
| 포커스 표시 | 키보드로 포커스를 옮긴 뒤 `focusStyle` 의 `hasIndicator` |
| 요소에 Tab 으로 도달 가능한지 | 가까운 요소에서 Tab·Shift+Tab 을 눌러 도달할 때까지 횟수를 센다 |
| 방향키·Home·End | 누를 때마다 `aria-selected`·`aria-valuenow`·화면 좌표를 읽는다 |

포커스 표시는 Tab 키로 포커스를 옮긴 상태에서 잰다. 코드로 `focus()` 만 호출하면 `:focus-visible` 이 맞지 않을 수 있다.

## 입력과 폼

| 대상 | 방법 |
|------|------|
| IME 조합 중 Enter | `composingEnter(locator)` 후 요청 수·입력값 변화. 합성 이벤트이므로 실제 입력기 확인은 사람 몫으로 남긴다 |
| 검색·정렬·페이지 이동 | 요청 주소와 쿼리 문자열을 기록해 값이 바뀌었는지 본다 |
| 오류 문구 연결 | 필수 입력에서 포커스를 뺀 뒤 `aria-invalid`, `aria-describedby`, 그 id 요소의 글자 |
| 복사 | 클립보드 읽기 권한을 준 뒤 `navigator.clipboard.readText()` 와 비교 |
| 달력·선택기 열림 | `showPicker` 를 감싸 호출 횟수를 센다 |

## 모양

| 대상 | 방법 |
|------|------|
| 겹침 | 요소 중심 좌표의 `document.elementFromPoint` 가 그 요소(또는 자식)인지 |
| 말줄임 | `scrollWidth > clientWidth` 와 `text-overflow` 계산값 |
| 색·다크 모드 | 테마를 바꾼 뒤 `color-scheme`·색 계산값 |
| 움직임 줄이기·고대비 | `page.emulateMedia({ reducedMotion: "reduce" })`, `{ forcedColors: "active" }` 뒤 열고 닫기와 계산값. 끝나면 `null` 로 되돌린다 |
| 애니메이션 | `animationName`·`transform` 계산값. 움직임 자체는 수치로 보기 어렵다 |

## 수치로 안 되는 것

- 정렬이 어긋나 보임, 여백이 답답함, 전체적으로 어색함 → 스크린샷을 열어 본다.
- 브라우저가 그리는 UI(달력 팝업, select 목록) → 스크린샷만 가능하다.
- 실제 입력기 조합, 스크린리더가 읽는 내용 → 확인할 수 없다. "확인 못 함"으로 보고한다.

## 원인 추적

결함을 찾으면 원인까지 본다.

- 스타일 문제: 문서의 모든 스타일시트를 훑어 해당 속성을 주는 규칙의 선택자와 출처 파일을 찾는다.
- 소비 앱의 전역 스타일이 라이브러리 요소를 덮는 경우가 많다. 규칙의 출처가 어느 쪽인지 구분한다.

## 수정 미리보기

고친 CSS 는 재배포 전에 `page.addStyleTag({ content })` 로 주입해 같은 측정을 반복할 수 있다.
주입으로 확인한 것은 "주입으로 확인"이라고 적는다. 실제 빌드로 확인한 것과 구분한다.
