# 보고 형식

## 구성

1. **전제** — 접속 주소, 로드된 빌드, 점검한 화면 수, 창 폭, 서버 데이터를 바꾸지 않았는지.
2. **통과** — 화면별로 확인한 것. 표로 정리한다.
3. **결함** — 증상, 재현 조건(창 폭 포함), 원인, 조치 여부.
4. **결정이 필요한 항목** — 아래 "결정이 필요한 항목" 형식.
5. **확인 못 함** — 확인하지 못한 항목과 이유. 사람이 봐야 할 것을 따로 적는다.
6. **달라지는 점** — 수정으로 소비 앱에서 달라질 동작.
7. **남은 상태** — 열려 있는 브라우저, 스크린샷 위치와 수, 재배포 필요 여부.

## 결정이 필요한 항목

개발자의 결정이 필요한 항목은 따로 모은다. 항목마다 아래를 적는다.

- 무엇을 정해야 하는가
- 선택지와 각 선택지가 화면에서 어떻게 달라지는가
- **참고할 출처** — 웹 표준 주제면 `modern-web-guidance` 가이드 id 와 해당 규칙, 그 규칙의 전제와 브라우저 지원 상태.
  프로젝트 규칙이나 요구사항이 근거면 그것. 없으면 "출처 없음, 화면 관찰만".
- 점검한 쪽의 의견(있으면)

출처는 참고용이다. 가이드와 요구사항이 다르면 그 차이를 적고 결정은 개발자에게 둔다.

## 근거 표기

시각적 판단은 근거를 구분해 적는다.

| 표기 | 뜻 |
|------|-----|
| 스크린샷 | 이미지를 열어 봤다 |
| 수치 | 좌표·스타일·요청 수 등을 쟀다 |
| 주입 확인 | 고친 CSS 를 화면에 주입해 쟀다. 실제 빌드로는 확인하지 않았다 |
| 합성 | 실제 입력 대신 합성 이벤트로 확인했다 |
| 추측 | 코드만 읽었다 |

"깨져 보인다", "정상이다" 같은 문장에는 위 표기 중 하나가 붙어야 한다.

## 쓰지 않을 것

- 확인하지 않은 항목을 통과로 적지 않는다.
- 측정하지 않은 항목(layout shift 등)을 "문제없음"으로 적지 않는다. "측정하지 않음"으로 적는다.
- 한 소비 앱의 결과를 전체의 안정성으로 적지 않는다.
- 계정 비밀번호를 적지 않는다.
