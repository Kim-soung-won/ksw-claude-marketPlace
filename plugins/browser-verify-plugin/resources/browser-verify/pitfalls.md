# 자주 겪는 문제

결과가 "실패"로 나오면 먼저 여기를 본다. 절반은 점검 스크립트 쪽 문제다.

## 스크립트 쪽 문제

| 증상 | 원인 | 대응 |
|------|------|------|
| 첫 화면이 빈 화면으로 찍힌다 | 로딩이 끝나기 전에 읽었다 | 몇 초 기다린 뒤 다시 읽는다. 로그인 화면으로 넘어갔는지 주소를 확인한다 |
| 버튼을 못 찾는다 | 이름이 글자가 아니라 `aria-label`·`title` 에만 있다 | 버튼의 HTML 을 출력해 보고 선택자를 고친다 |
| 엉뚱한 다이얼로그가 열린다 | 같은 클래스의 버튼이 여러 개다 | 글자나 `aria-label` 로 좁힌다 |
| 날짜 입력에서 Tab 이 안 넘어가는 것처럼 보인다 | 날짜 입력은 년·월·일 칸마다 Tab 이 한 번씩 필요하다 | 넘어갈 때까지 횟수를 센다 |
| Tab 으로 요소에 도달하지 못한다 | 중간 요소가 Tab 을 여러 번 소비한다 | 가까운 요소에서 Shift+Tab 으로 거꾸로 접근한다 |
| 행을 눌러도 상세가 안 열린다 | 셀 클릭이 아니라 행 안의 버튼으로 열린다 | 화면 구성을 다시 읽는다 |
| 끌기가 안 되는 것처럼 보인다 | 좌표 계산이 틀렸다 | 요소의 좌표를 다시 읽어 재시도한다 |
| 포커스 표시가 없다고 나온다 | 코드로 `focus()` 만 호출했다 | Tab 키로 포커스를 옮긴 뒤 잰다 |
| 번들 파일에서 문자열 검색이 빈 결과다 | 한 줄이 매우 길어 검색 도구가 실패한다 | 스크립트 언어로 직접 찾는다 |

## 클릭 실패가 결함인 경우

"요소가 다른 요소에 가려져 클릭할 수 없다"는 오류는 스크립트 문제가 아니라 실제 레이아웃 결함일 수 있다.
스크린샷을 열어 확인하고, 창 폭을 바꿔 `overflowReport` 로 잰다.

## 점검 범위가 만든 구멍

| 구멍 | 대응 |
|------|------|
| 창 폭을 하나만 썼다 | 폭 여러 개를 기본으로 잰다 |
| 수치가 정상이라 스크린샷을 열지 않았다 | 화면마다 한 장은 연다 |
| 자동 테스트가 통과해 화면을 보지 않았다 | 소비 앱의 전역 스타일과 만나야 드러나는 문제가 있다. 실제 화면에서 확인한다 |
| 코드만 읽고 점검 절차를 썼다 | 절차에 틀린 항목이 섞인다. 화면 구성을 먼저 읽고 쓴다 |
| 한 소비 앱만 봤다 | 다른 앱에서의 회귀는 확인되지 않은 것으로 보고한다 |

## 환경

- 여러 앱을 한 기기에 모두 띄우기 어려우면 점검 범위가 일부 모듈로 줄어든다. 줄어든 범위를 보고서에 적는다.
- 떠 있지 않은 remote 의 로드 오류가 콘솔에 섞인다. 점검 대상의 오류와 구분한다.
