# 안전 장치

점검은 실제 데이터가 있는 환경에서 돌 수 있다. 사용자가 명시적으로 허용하지 않은 변경은 하지 않는다.

## 기본 규칙

- 저장·삭제·배포·중지·전송처럼 서버 데이터를 바꾸는 동작은 실행하지 않는다.
- 사용자가 허용한 범위가 있으면 그 범위만 따른다. 허용은 그 대상에만 해당한다.
- 판단이 서지 않으면 누르지 않고 "확인 못 함"으로 남긴다.

## 확인 창이 필요한 점검

"다이얼로그 위에 뜬 확인 창"처럼 확인 창 자체를 봐야 할 때가 있다.

1. 버튼을 누르기 전에 앱 코드를 읽어, 누르면 확인 창이 먼저 뜨고 확인을 눌러야 실행되는지 확인한다.
2. 바로 실행되는 버튼이면 누르지 않는다.
3. 확인 창은 Escape 로 닫는다. 확인 버튼에 포커스가 있는 상태에서 Enter 를 누르지 않는다.
4. 닫은 뒤 `mutations()` 가 비어 있는지 확인한다.

## 입력

- 폼에 값을 넣는 것은 괜찮지만 제출하지 않는다. 끝나면 Escape 로 닫는다.
- 채팅·검색처럼 Enter 가 전송인 입력은 실제 전송이 서버에 부담을 주는지 먼저 판단한다. 조합 중 Enter(합성)와 Shift+Enter 만으로 충분한 경우가 많다.

## 되돌리기

점검 중 바꾼 브라우저 상태는 끝나기 전에 되돌린다.

- 다크 모드, 창 폭, `emulateMedia` 설정
- 열어 둔 다이얼로그·패널
- 주입한 스타일(페이지를 다시 불러오면 사라진다)

## 매 스크립트 끝에서

`mutations()` 를 출력에 포함한다. 이 목록은 GET 이 아닌 요청 전부라서, 검색·조회에 POST 를 쓰는 API 가 섞인다.
화면을 열기만 한 상태(`survey.cjs`)의 목록을 기준선으로 삼고, 조작 뒤 새로 생긴 요청만 본다.
새로 생긴 요청이 데이터를 바꾸는 것이면 어떤 조작이 원인인지 확인하고 사용자에게 알린다.
인증 토큰 갱신처럼 조작과 무관한 요청은 `watchRequests(page, { ignore: /정규식/ })` 로 뺀다. 기본값은 아무것도 빼지 않는다.
