# 진단과 호환성

## 발견·설치 실패

클라이언트와 버전, 카탈로그 등록 여부, source 해석 기준, 매니페스트 파싱,
플러그인 활성화 상태, 신뢰 범위를 차례로 좁힌다. 설치 성공 뒤 호출이 안 되면
스킬의 탐색 경로·description·세션 반영을 확인한다. 캐시 전체 삭제를 첫 조치로 삼지 않는다.
수정 뒤 처음 실패했던 명령이나 작업을 다시 확인한다.

## Claude Code에서 이식

| 요소 | 확인할 차이 |
|---|---|
| 스킬·리소스 | 상대 경로, 프로젝트 스킬 탐색 위치, 제품별 도구 명칭 |
| 에이전트 | 등록 형식, 위임 방식, 컨텍스트 격리, 모델·권한 |
| 커맨드 | 명시적 작업 진입점으로서 스킬로 제공할 수 있는지 |
| 훅 | 이벤트 입력·출력, matcher, 실패·승인 처리 |
| 세션 분석 | 로그 형식과 필드, 서브에이전트 연결, 누락 처리 |
| 카탈로그 | 인식 가능한 위치·스키마와 실제 구성 요소의 지원 여부 |

`${CLAUDE_PLUGIN_ROOT}`를 확인하지 않은 Codex 변수로 치환하지 않는다. 문서 상대 경로나
실제 설치 방식이 제공하는 경로를 사용한다. 경로를 바꾸면 참조하는 파일도 함께 확인한다.
지식은 공유하되 실행 규약은 제품에 맞춘다. 에이전트를 스킬로 바꿀 때 격리와 요약 반환이
사라지는지 평가한다. transcript는 안정적인 인터페이스라고 가정하지 않고, 필요한
파서·정규화 계층을 제품별로 구분한다.

## 결과 보고

원인마다 관찰한 파일·필드·오류를 연결한다. 확인한 원인과 추정을 구분하고,
수정한 항목, 재현 명령의 결과, 실제 클라이언트에서 남은 확인을 짧게 제시한다.
