# Codex 확장·운영 문서

사용자가 지정한 Codex 실행 환경(CLI·앱·IDE·클라우드)과 대상 범위(프로젝트·사용자·팀)를
유지한다. 이 스킬은 Codex 자체의 확장을 다룬다. 일반 애플리케이션 코딩은 해당 작업의 규칙을 따른다.

## 작업 방식

1. 관련 로컬 설정·매니페스트·오류와 사용 가능한 CLI의 `--version`, 해당 하위 명령의
   `--help`를 읽어 실제 환경을 확인한다. 설정 파일에서 인증 값은 응답에 노출하지 않는다.
2. 요청한 기능의 최신 공식 문서를 조회한다. 공식 문서 검색 도구가 있으면 사용하고,
   없으면 웹 검색을 `developers.openai.com`, `learn.chatgpt.com`, `platform.openai.com`으로
   제한한다. 검색 요약만으로 규격을 확정하지 말고 해당 페이지를 열어 확인한다.
   [공식 문서 진입점](references/sources.md)에서 필요한 주제만 선택한다.
3. 생성·수정은 [작성과 검증](references/authoring.md), 설치 실패·이식은
   [진단과 호환성](references/diagnostics.md)의 해당 절차를 읽는다.
4. 사용자가 실행을 요청했다면 설명에서 멈추지 말고 요청한 파일을 작성·수정하고 검증한다.
   기존 설정의 관련 필드만 변경한다. 진단 요청이면 원인·근거·수정안을 먼저 제시한다.

설치된 `plugin-creator`, `skill-creator`가 작업에 적합하면 그 절차를 활용한다.
없어도 공식 규격과 대상 저장소 규약으로 작업할 수 있어야 한다. 도구·스킬 이름을
호출 가능 여부 확인 없이 전제하지 않는다.

## 근거와 완료 기준

- 제품 지원 여부·명령·스키마·모델 이름을 Claude Code의 대응 기능에서 추측하지 않는다.
- 문서와 설치 버전이 다르면 차이를 설명하고, 실제 버전에서 지원되는 방법을 선택한다.
- 공식 문서에 접근하지 못하면 로컬에서 확인한 사실과 미확인 규격을 구분한다.
  최신 규격을 확인했다고 말하지 않는다. 가능한 정적 검증은 계속한다.
- 응답에는 변경 결과 또는 진단 결론, 수행한 검증, 남은 미확인 사항, 근거 페이지 링크를 담는다.
  JSON/TOML 파싱 성공과 실제 스킬 선택·도구 실행 성공을 구분한다.
