# 프로젝트 기록 양식

이 파일은 에이전트용 양식 모음이다. 필요한 양식만 해당 프로젝트 파일로 작성한다. 빈 양식을 학습 완료 기록으로 사용하지 않는다.

## AGENTS.md 학습 프로젝트 구간

AGENTS.md에 추가한다. CLAUDE.md에는 `@AGENTS.md` 가져오기 줄만 둔다. 꺾쇠 안내는 실제 값으로 바꾼다.

```markdown
<!-- learning-coach:start -->
## 학습 프로젝트

이 폴더는 learning-coach 스킬로 진행하는 개인 학습 프로젝트다.

- 학습 시작·재개·복습·종료 요청에는 learning-coach 스킬을 따른다. 세션이 새로 시작됐다는 이유만으로 학습을 재개하지 않는다.
- 학습 개요·커리큘럼·현재 단위는 [학습 개요](./docs/README.md)에 있다. 재개할 때 이 문서, 현재 단위 문서, `.learning/sessions/`의 최신 기록, 관련 예시 코드를 먼저 읽는다.
- 단위별 설명·실험·평가·회고는 `docs/units/`에 둔다. 예시 코드는 `<예시 코드 경로>`에 둔다.
- 설명 선호와 Notion 대상 페이지는 학습 개요를 따른다.
- 학습 중 코드 수정 같은 다른 작업 요청은 복귀 지점을 남기고 먼저 수행한다.
<!-- learning-coach:end -->
```

## docs/README.md (학습 개요)

사람이 IDE에서 읽는 과정의 첫 문서다. 단위 문서를 추가·이름 변경할 때 아래 표를 같은 작업에서 갱신한다.

```markdown
# <과정 이름> 학습 개요

현재 단위: [<번호> · <주제>](./units/<번호>-<주제>.md) · [Notion](<대상 페이지 URL 또는 미설정>)

## 목표와 경험

- 배우려는 목표:
- 사용자가 설명한 관련 경험:
- 설명·자료 선호: IDE Markdown, 코드, Mermaid / 터미널 짧은 응답
- 과정의 기존 기록 위치:
- Notion 대상 페이지 ID: 미설정이면 미설정
- 프로젝트를 다른 환경으로 옮기는 방법: 확인되지 않으면 미확인

## 커리큘럼

| 단위 문서 | 이해하려는 것 | 대표 예시 | 종료 시험에서 확인할 판단 | 필수/선택 | 상태 |
| --- | --- | --- | --- | --- | --- |
```

날짜가 아니라 목표로 순서를 정한다. 확장 주제를 기존 단위와 연결한다. 단위 문서는 docs/units/<두 자리 번호>-<주제>.md로 만들고 [단위 문서 양식](worksheet.md)을 쓴다.

## .learning/sessions/기록ID.md

docs/에는 읽기 좋은 핵심을, 이 파일에는 재개·동기화에 필요한 원본 이력을 남긴다.

- 기록 ID / 학습 세션 ID / 기반 기록 ID:
- 실제 학습 일시와 도구:
- 원래 목표 / 현재 단위 / 단위 상태:
- 사용한 파일·내용 해시·커밋:
- 사용자 답변과 최초 이해:
- 힌트·교정 및 이해 재확인:
- 시험 진행·철회·미응답:
- 실험 실행 주체·환경·명령·관찰:
- 설명만 했거나 미실시인 항목:
- 복습 대상:
- 확장 중인 주제와 돌아갈 지점:
- 유효한 대기 질문 또는 없음:
- 다음 행동:
- 동기화 상태와 보류 이유:

## .learning/sync/outbox/기록ID.json

필드: schemaVersion(1), recordId, sessionId, baseRecordId(null 가능), targetPageId(null 가능), createdAt, content(동기화할 원문), contentHash(SHA-256), status(pending/synced/conflict).

ID는 최초 저장 때 생성하고 재시도 시 유지한다. 내용 수정은 새 기록 ID와 이전 기반 ID로 남긴다. 대상이 없으면 pending으로 보존하고 설정 전 외부 저장하지 않는다. receipts에는 recordId, contentHash, remoteUrl, verifiedAt을 남긴다.

이 양식은 스키마 검증기나 동시 쓰기 잠금의 구현을 뜻하지 않는다.
