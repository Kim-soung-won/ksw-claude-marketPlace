# 평가와 복습

## 마무리 시험

학습한 단위의 핵심으로 2~3문항을 준비하되 한 번에 하나만 공개하고 답변을 기다린다. 문항 수보다 명확성과 실제 판단을 우선한다. 설명·예측·진단 중 목표에 맞는 유형을 선택한다.

전송 전 다음을 검사한다.

1. 대상 파일·함수·실행 환경·관찰 시점과 판단 대상 하나가 질문 문장에 있는가? 측정값을 예측하는 문제인지 개념·원인을 설명하는 문제인지 구분했는가? 측정 문제면 지표 이름과 관측 조건(시점·GC 등)을 지정했고, 개념 문제면 “메모리 사용량”처럼 여러 지표로 읽히는 표현 대신 판단할 대상 자체(예: 배열이 참조해 해제할 수 없는 파일 데이터의 총량)를 적었는가?
2. 실제 코드와 가상 변경을 구분했는가? 조건끼리 모순되지 않는가?
3. 문제·주석·Mermaid에 정답이나 핵심 추론을 이미 제시하지 않았는가?
4. 앞서 배운 범위이며 아직 독립적으로 확인하지 않은 판단인가?
5. 결과만 맞혀도 원인을 이해했다고 평가하게 되는 문제는 아닌가?

같은 설명에 여러 지표(예: rss·heapUsed·arrayBuffers)가 등장했다면 질문에 어느 것을 묻는지 반드시 적는다. 풀이 방향을 덧붙이는 것으로 판단 대상 지정을 대신하지 않는다.

실행 조건을 명시하는 것과 풀이 힌트를 주는 것은 구분한다. 예를 들어 CPU 작업의 위치가 비교 대상이면 코드로 조건을 제공하되 “메인 스레드가 막히므로”라는 결론을 질문에 넣지 않는다.

## 답변 처리

정확한 부분과 보완할 부분을 구분한다. 핵심 오답은 설명·시각화 후 재설명 또는 적용으로 이해를 확인하고 복습 항목에 남긴다. 한 번 교정 직후 정답을 독립 숙달로 올리지 않는다. 계속 막히면 설명 방식을 바꾸거나 휴식 선택지를 제공한다. 무한 재시험은 하지 않는다.

질문 결함은 철회하고 사용자 오답으로 기록하지 않는다. 미응답·중단 역시 오답이 아니다. 종료 요청이면 확인하지 못한 부분과 다음 위치를 저장한다.

## 기록

개념별 상태는 미학습 / 설명함 / 도움 후 이해 / 독립 이해 확인 / 지연 복습 확인으로 구분한다. 답변 요약, 질문 조건, 힌트·교정 여부, 근거 파일을 함께 남긴다. 코드 생성·실행 검증은 개념 상태와 별개다.

상태를 올리거나 내리면 단위 문서 상단·복습 표·본문의 이전 상태 문장을 함께 정리한다. 이전 상태는 날짜와 함께 과거형 이력으로 남긴다. 다른 세션이 이미 확인한 개념을 미확인으로 읽지 않게 한다.

단위 완료는 내용과 유효한 종료 평가가 끝났을 때 표시한다. 도움 후 이해 항목은 완료한 단위에서도 복습 대상으로 유지한다. 이해 확인 전에 중단하면 해당 평가를 완료로 만들지 않는다.

## 다음 학습의 복습

학습 진입 때 미확인·도움 후 이해 항목부터 작은 상황 하나로 확인한다. 새 도구 세션에서도 같은 기록을 사용한다. 같은 학습 세션의 매 턴마다 복습을 재시작하지 않는다.

다시 모르면 바로 설명한다. 조건이 다른 상황에서 도움 없이 설명한 근거가 있을 때만 상태를 올린다. 반복 횟수나 짧은 “알았어”를 근거로 자동 완료하지 않는다.
