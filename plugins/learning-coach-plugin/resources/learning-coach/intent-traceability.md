# 인터뷰 확정 의도와 요구사항 반영표

이 문서는 학습 하네스를 만들기 전에 진행한 Interview Me 대화에서 사용자가 명시적으로 확정한 의도와 현재 플러그인의 반영 위치를 연결한다. 사용자는 첫 의도 정리와 후속 운영 방식 정리에 각각 확정 의사를 밝혔다. 아래 발언은 대화의 핵심 표현을 인용하거나 요약한 것이다.

규칙을 수정하거나 반영 여부를 검토할 때 읽는다. 매 학습 턴마다 읽을 필요는 없다. 이 문서를 추가하면서 기존 학습 절차·description·문서 구조를 변경하지 않았다. 반영표의 “지침 반영”은 실제 호스트에서 동작을 검증했다는 뜻이 아니다.

## 확정 의도

- **원하는 결과:** 모호한 질문을 다시 명확히 해달라고 요구하는 대화와 기다림을 줄여 학습 피로도를 낮춘다.
- **사용자와 맥락:** 본인의 학습 방식이 최우선이다. 여러 작업 사이에 alt-tab으로 참여하므로 지속적인 몰입을 전제하지 않는다.
- **만드는 이유:** 7일 Node.js 학습에서 확인한 효과적인 방식과 반복된 불편을 다른 주제·도구·환경에서도 개선한다.
- **학습 경험:** IDE의 Markdown·실제 코드 파일·Mermaid로 이해를 돕고 터미널에서 답한다. 막히면 바로 설명하고 추후 복습한다.
- **진행:** 호기심에 따라 확장하되 예정된 커리큘럼과의 관계 및 복귀 경로를 유지한다. 참여 저하 신호에는 선택지로 동기·여유를 확인하며, 별도 작업 요청은 우선 처리한다.
- **성공 기준:** 질문 명확화 재요청과 체감 피로가 줄고, Codex·Claude Code 및 다른 환경에서 진도를 다시 설명하지 않고 이어갈 수 있다. 수치 목표는 확정하지 않았다.
- **범위 밖:** 첫 버전의 타인 대상 일반화, 초기 진단 시험, 날짜별 진도 강제, 일반 작업 중 복습 강요, 정답을 미리 공개한 형식적 질문, 진도량 극대화.

## 합의와 후속 설계의 경계

이 인터뷰는 학습 경험과 진행 원칙을 확정했다. 저장소 전용 여부, 구체적인 파일 경로, 단위별 문서 분할, AGENTS.md·CLAUDE.md 연결 방법, 세션마다 코치 감상을 남기는 정책까지 이 인터뷰에서 확정한 것으로 소급하지 않는다.

현재 플러그인은 이 항목들을 후속 설계로 포함한다. [0.2.0 변경 이력](../../CHANGELOG.md)에 해당 변경이 기록돼 있다. 별도 대화에서 추가 합의됐는지는 이 인터뷰 기록만으로 판정하지 않는다. 이번 문서는 그 정책을 삭제·수정하지 않고 출처 범위만 구분한다.

특히 “프로젝트에 보존”과 “다른 장치로 전송 완료”는 다르다. 현재 [동기화 절차](persistence.md)는 그 한계를 명시하며 자동 Git 전송을 가정하지 않는다.

## 유지 방법

규칙을 바꿀 때 관련 I 번호와 위치·상태를 함께 검토한다. 새로운 선택은 합의 또는 설계 제안 중 어느 것인지 표시한다. 지침 작성, 자동화 구현, 실제 행동 검증을 구분하여 미구현을 완료로 올리지 않는다. 문서 경로를 바꾸면 이 표의 링크도 갱신한다.
