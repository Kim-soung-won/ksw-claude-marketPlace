# 프로젝트 기록과 Notion 동기화

## 시작할 때

학습은 학습 전용 저장소에서 진행한다. 프로젝트 지침과 기존 학습 기록 위치를 먼저 읽는다. 설치된 스킬 폴더에는 개인 진도를 쓰지 않는다.

기록은 읽는 주체에 따라 나눈다. [기록 양식](assets/records.md)을 기준으로 준비한다.

| 위치 | 내용 |
| --- | --- |
| docs/README.md | 학습 개요: 목표·경험·선호·Notion 대상·커리큘럼·현재 단위 |
| docs/units/ | 단위별 설명·Mermaid·실험·평가·복습·회고와 조언 |
| .learning/sessions/ | 재개에 필요한 세션 원본 이력 |
| .learning/sync/ | Notion outbox·receipts |

이미 docs/에 다른 구조의 학습 기록이 있으면 그 경로를 따르고 새 구조를 겹쳐 만들지 않는다. 실제 코드·사용자 기록을 새 양식으로 무조건 교체하지 않는다.

### 세션 지침 구성

학습은 프로젝트 폴더 단위로 진행한다. Claude Code와 Codex 세션이 시작할 때 자동으로 읽는 프로젝트 지침 파일에 학습 프로젝트임을 알려, 새 세션에서도 같은 기록을 찾아 이어가게 한다.

1. 최초 설정 때 프로젝트 루트의 AGENTS.md와 CLAUDE.md를 확인한다. 두 파일의 기존 내용과 서로의 가져오기(@AGENTS.md) 관계를 먼저 읽는다.
2. 공통 내용은 AGENTS.md 한 곳에 둔다. [기록 양식](assets/records.md)의 학습 프로젝트 구간을 실제 경로로 채워 추가한다. Codex는 AGENTS.md를 읽는다.
3. Claude Code는 CLAUDE.md를 읽으므로 CLAUDE.md에 `@AGENTS.md` 가져오기 줄이 있게 한다. 파일이 없으면 이 줄만 담아 만든다. 이미 AGENTS.md를 가져오면 그대로 둔다. 같은 구간을 두 파일에 복제하지 않는다.
4. 기존 파일은 덮어쓰지 않는다. learning-coach 표시 주석으로 감싼 구간만 추가·수정하고 사용자 지침은 보존한다. 모든 세션의 동작이 바뀌므로 처음 쓰기 전에 추가할 내용과 파일을 보여 주고 확인을 받는다.
5. 지침에는 자주 바뀌지 않는 연결만 둔다. 기록 위치, 예시 코드 위치, 스킬 적용 조건을 적는다. 진도·대기 질문·단위 목록·Notion 페이지 ID처럼 갱신되는 값은 docs/README.md와 .learning/에 두고 지침에서 학습 개요를 가리키기만 한다. 인증 정보는 적지 않는다.
6. 재개 때는 구간이 있는지와 경로가 실제와 맞는지만 확인한다. 어긋날 때만 고치고 매 세션 다시 쓰지 않는다. 사용자가 거절하면 지침 파일 없이 docs/와 .learning/ 기록만으로 진행한다.

도구가 달라도 같은 프로젝트 기록을 읽는다. 이전 학습 목표·대기 질문·복귀 경로·복습 항목·코드 기준을 확인한다. 기록과 실제 파일이 다르면 원인을 대조하고 불명확한 판단만 사용자에게 묻는다. 사용자 답변·에이전트 실행·미실시는 구분한다.

## 기록 저장

원래 목표, 현재 단위, 다음 행동, 질문 하나 또는 없음, 복귀 경로, 도움 여부, 사용한 파일·가능하면 해시와 커밋, 실험 명령·환경·실행 주체·결과를 남긴다. docs/의 단위 문서에는 읽기 좋은 핵심만 남기고 이력은 .learning/sessions/에 보관한다.

중단 시에도 먼저 로컬 저장한다. 오답 교정·평가·확장 복귀처럼 재개에 필요한 변화는 진행 중에도 기록해 갑작스러운 세션 종료에 대비한다. 학습 세션 ID와 기록 ID를 유지하며 재시도 때 새 ID를 만들지 않는다.

state.json 기반의 원자적 저장·동시 수정 방지 프로그램은 아직 없다. 현재는 쓰기 직전 파일을 재확인하고 예상하지 못한 변경이 있으면 덮어쓰지 않는다. 다른 도구와 동시 쓰기의 안전성을 보장했다고 말하지 않는다.

## Notion 시작·종료 동기화

학습을 시작하거나 마칠 때 이 절차를 수행한다. 매 턴마다 동기화하지 않는다. 대상은 프로젝트 설정 또는 기존 기록의 정확한 페이지 ID를 사용한다. 없으면 최초 설정 때 사용자에게 목적지를 확인한다. Node.js Sprint의 페이지를 다른 과정에 재사용하지 않는다.

1. 먼저 .learning/sync/outbox/에 원문을 보존한다. 기록 ID, 내용 해시, 대상 페이지 ID, 생성 시각, 기반 기록 ID, pending 상태를 함께 저장한다. 인증 정보는 저장하지 않는다.
2. 연결된 Notion 도구를 발견하고 현재 명세·사용 지침을 읽는다. 읽기·쓰기 수단이 없거나 실패하면 로컬 기록을 유지하고 미동기화 수를 알려준다.
3. 대상 페이지를 직접 조회한다. 로컬과 원격의 학습 기록을 비교한다. 한쪽에만 있는 기록은 보존하고, 시각만으로 이해도·진도를 덮어쓰지 않는다.
4. 원격에 기록 ID·내용 해시를 담은 식별 가능한 관리 구간을 사용한다. 동일 ID가 이미 있으면 실제 내용도 확인한다. 같은 내용이면 중복 쓰지 않는다. 원격 사용자가 수정했다면 마커만 보고 일치 처리하지 않는다.
5. 같은 기반에서 서로 다른 진도가 파생됐으면 양쪽 원문을 보존한다. 판단할 수 없는 차이만 사용자에게 확인한다. 전체 페이지 교체 대신 관리 구간 수정·추가를 사용한다.
6. 원격 저장을 확인한 뒤 receipts에 원격 위치·기록 ID·내용 해시·확인 시각을 저장하고 outbox를 synced로 바꾼다. 응답이 모호하면 먼저 재조회한다. 조회에도 실패하면 pending 유지, 같은 진입/종료에서 반복 재시도하지 않는다.
7. 시작 시 원격에만 있는 최신 인계는 프로젝트에 보존한 뒤 실제 파일과 대조한다. 내용이 없는 예시 파일을 실행한 것처럼 가정하지 않는다.

이것은 에이전트 수행 절차이며 트랜잭션·재시도 엔진이 아니다. 신뢰성 자동화는 후속 구현·테스트가 필요하다.

프로젝트에 보존됐다고 다른 장치로 전달된 것은 아니다. Git 등 이동 수단이 확인되지 않으면 현재 프로젝트에만 기록됐다고 알린다. 자동 commit·push나 공유 권한 변경은 하지 않는다.

## 종료 알림

종료 전에 단위 문서에 코치 감상을 추가한다. 확인된 이해, 남은 복습, 다음 위치, 로컬 저장과 Notion 반영 상태를 짧게 알려준다. 관리·종료 요청에 새 시험을 붙이지 않는다.
