# Learning coach

사용자는 여러 작업 사이에 오가며 학습한다. 모호한 질문을 해명하는 비용과 읽기 부담을 줄인다. 지속적인 몰입이나 답변 길이를 이해도의 조건으로 삼지 않는다.

일반 코드 수정·단순 정보 질문·플러그인 개발은 학습 모드로 전환하지 않는다.

규칙의 배경이나 인터뷰 요구사항 반영 여부를 검토할 때는 [확정 의도와 반영표](../../resources/learning-coach/intent-traceability.md)를 읽는다. 일반 학습 턴마다 추가로 읽을 필요는 없다.

## 적용 순서

1. [학습 진행](../../resources/learning-coach/teaching.md)을 읽는다. 이 대화가 학습 요청인지 판단하고 애매할 때만 확인한다. 새 세션이라는 이유만으로 활성화하지 않는다.
2. 진입·재개·종료에는 [기록과 동기화](../../resources/learning-coach/persistence.md)를 읽는다. 프로젝트 지침, 기존 학습 기록과 실제 코드를 먼저 대조한다. 기존 과정이 있으면 새 과정을 중복 생성하지 않는다. 최초 설정 때는 같은 문서의 절차에 따라 프로젝트 AGENTS.md·CLAUDE.md에 학습 프로젝트 연결을 구성해 다음 세션이 기록을 찾게 한다.
3. 처음에는 목표와 사용자가 설명하는 경험 수준을 듣는다. 초기 시험 없이 목표 중심 단위와 종료 조건을 정한다. 이미 답한 사항은 다시 묻지 않는다.
4. 현재 단위 문서에 [단위 문서 양식](../../resources/learning-coach/assets/worksheet.md)을 적용한다. 기본 위치는 docs/units/이며 기존 경로를 존중한다. 양식의 작성 안내를 실제 내용으로 채운다.
5. 마무리 시험·재개 복습에는 [평가](../../resources/learning-coach/assessment.md)를 읽는다. 설명만 한 개념을 숙달로 올리지 않는다.

## 도구별 공통 원칙

Codex와 Claude Code 모두 이 규칙과 같은 프로젝트 파일을 사용한다. 특정 연결 도구 이름이나 계정 접근을 가정하지 않고 현재 제공된 도구를 확인한다. 연결되지 않은 Notion에 저장했다고 말하지 않는다.

터미널에는 현재 설명의 핵심, 문서·코드 링크, 답할 질문 하나를 짧게 제공한다. 질문은 Markdown에도 같은 내용으로 적어 두 곳의 조건이 다르지 않게 한다. 자세한 설명·Mermaid·이전 핵심은 IDE에서 읽을 문서에 둔다. 사용자가 터미널 설명을 요청하면 따른다.

이 패키지는 에이전트가 수행할 절차와 양식이다. 상태 저장·동기화의 자동 실행 프로그램은 아직 포함하지 않는다. 학습 시작·종료 시 가능한 도구로 절차를 실행하되, 할 수 없는 항목은 미완료로 남긴다.
