# /ingest — 대화 결정화(결정화층)

이 커맨드는 **지금 진행 중인 대화**에서 재사용 가치가 있는 지식을 뽑아 정식 위키 노트로
만든다. 개인 기억 보철의 "결정화 레이어"에 해당하며, 큐레이션된 지식(`_inbox/` → 이후
`20 Areas/`)으로 승격시키는 단계다.

## 핵심 제약 — 대화 컨텍스트는 메인 에이전트만 안다

wiki-manager는 subagent라서 **이 대화 기록을 보지 못한다**(새 컨텍스트로 시작). 따라서
결정화할 실질 내용의 추출은 반드시 대화 컨텍스트를 가진 **현재(메인) 에이전트가 먼저**
수행하고, 그 추출 결과를 위임 프롬프트에 담아 전달해야 한다. "대화를 요약해서 노트로
만들어줘"라고만 위임하면 subagent는 빈손이다.

## 절차

1. **실질 지식 추출(메인 에이전트가 수행)**: 대화에서 나중에 다시 찾아볼 가치가 있는 것을
   정리한다 — 무엇을·왜·어떻게 알게/결정했는지, 핵심 결론·규칙·수치, 코드/명령, 트러블슈팅
   원인과 해결, 논의된 트레이드오프. 인자(`$ARGUMENTS`)가 있으면 그 주제로 좁힌다. 원본
   API 경로·타입명·수치 등은 축약하거나 추측하지 말고 정확히 옮긴다.

2. **노트 타입 판단**: 대부분 기술 학습이지만, "왜 A 대신 B" 같은 아키텍처 의사결정이면
   ADR, 장애 원인·조치면 Incident, 미팅 정보면 Meeting 성격일 수 있다. 애매하면 기본값
   (Tech Learning)으로 진행하되 한 줄로 확인한다. (템플릿·번호 규칙의 상세는 wiki-manager가
   `note-capture.md`에서 처리한다.)

3. **wiki-manager 에이전트에 위임**: 1에서 추출한 실질 내용을 **위임 프롬프트에 그대로
   담아** wiki-manager 에이전트를 호출한다. wiki-manager는 note-capture 절차로 vault
   컨벤션(템플릿·frontmatter·Tag Index·파일명)에 맞는 노트를 `_inbox/`에 저장하고, 이어서
   wikilink-linker 소규모 경로로 관련 노트와 위키링크를 연결한다.
   - 원본 대화에서 이미 언급된 vault 노트가 있으면 위임 프롬프트에 함께 알려 링크 후보로
     삼게 한다.
   - Claude가 첨언한 보완/토론 내용이 있으면, 원본과 구분되도록 `> [!INFO] 심화 보완`
     콜아웃으로 분리해달라고 위임 프롬프트에 명시한다(기존 노트들과 동일한 패턴).

4. **보고**: wiki-manager가 생성한 노트 경로와 연결한 위키링크 목록을 사용자에게 전달한다.
   저장은 `_inbox/`까지이며, 최종 폴더 이동·status 상향은 vault 룰상 사람이 검토 후 별도로
   수행한다.

5. **커밋은 하지 않는다** — 사용자가 명시적으로 요청할 때만.

## /log 와의 관계

`/log`는 넓은 캡처(Daily Note에 요약 append, recall 우선), `/ingest`는 선별적 결정화
(위키 노트 + 위키링크, precision 우선)다. 워크플로우는 보통 캡처 → (자주 다시 보게 되면)
결정화 순으로 흐른다. 승격 기준을 미리 빡세게 정하지 말고, **실제로 반복 참조하게 되는
로그를 `/ingest`로 끌어올리는** pull 기반으로 운용한다.
